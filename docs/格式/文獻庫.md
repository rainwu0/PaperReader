# 文獻庫格式

> **0.x 期間可能變。** 這份文件描述 PaperReader 0.x 的文獻庫格式。正式版之前格式還可能調整；調整時照第 13 節的相容規則，舊資料照樣讀得到。

這份給想在應用以外讀寫文獻庫的人：在電腦上寫腳本整理文獻、做另一個閱讀器、把資料轉到別的軟體。它只寫檔案長什麼樣子與讀寫時要遵守的規則，不寫應用內部怎麼實作。

## 1. 資料夾配置

```text
<文獻庫>/                                    Android 上預設是 Documents/PaperReader/
  library.json                               文獻庫的設定與群組
  papers/
    Chen 2025 - An Example Paper/            一篇文獻一個資料夾
      paper.json                             描述檔
      source.pdf                             原文
      translation.pdf                        自己加入的譯本（選用）
      translation-overlay.json               譯文疊加檔（選用）
      translation-generated.pdf              產生的譯本 PDF（選用）
      digest.md                              重點筆記（選用）
      ink.json                               筆跡（選用）
      references.json                        參考文獻清單（選用）
  notes/
    Chen 2025 - An Example Paper.md          筆記檔，一篇一份
  logs/
    reading-<裝置代號>-2026-11.jsonl         閱讀紀錄，每台裝置、每個月一個
    changes-<裝置代號>.jsonl                 變更紀錄，每台裝置一個
  jobs/                                      保留，目前不使用
  .trash/                                    回收區
```

- `notes/`、`logs/`、`.trash/` 等資料夾用到時才建立。
- 名稱以 `.` 開頭的檔案與資料夾（例如 `.obsidian/`），應用掃描時略過，也不刪除；`.trash/` 是應用自己的回收區。
- 以 `.pr-` 開頭的是應用的暫存項目。應用只清理這個開頭的項目；別的工具不要用這個開頭。
- 根目錄與 `papers/` 底下出現應用不認得的檔案或資料夾：應用不動它、不報錯，只在應用的「檢查結果」裡列出。

## 2. 共通規則

| 項目 | 規則 |
|---|---|
| 文字編碼 | UTF-8，不加位元組順序記號 |
| JSON 排版 | 兩個空格縮排，結尾一個換行，欄位順序照本文件所列 |
| 欄位名稱 | 英文小寫，單字之間用底線 |
| 時間 | 世界協調時間，到毫秒，例如 `2026-11-13T08:25:02.123Z` |
| 代號 | ULID：26 個字元，由時間與亂數組成，各裝置自己產生、不會撞號。劃線、筆跡等小項目的代號是一個前綴加小寫的 ULID，例如 `h-01jck5a7m3q9x2v8b4n6r0t1yz` |
| 指紋 | 檔案全部內容的 SHA-256，64 個小寫十六進位字元 |
| 路徑 | 相對於所在的文獻資料夾，用 `/` 分隔；不可含 `..`、不可是絕對路徑；以 `@` 開頭的保留不用 |
| 不知道的值 | 寫 `null`，不猜 |
| 不認得的欄位 | 每一層的物件都要原樣保留，寫回去時不可丟掉 |
| 寫入 | 先在同一個資料夾寫成暫存檔（`.pr-tmp-<代號>`），寫完再改名蓋過正式的檔，中途中斷不會留下半個檔 |
| 改之前先比對 | 寫一份檔之前，先確認它的內容和自己讀到時相同（比對整份檔的 SHA-256）；不同表示別處改過，不要蓋掉 |
| 頁序與座標 | 頁序從 0 起算，是那一份 PDF 的頁序。座標是 PDF 頁面座標，單位是點（1/72 吋），原點在頁面左下，寫入時取到小數兩位 |
| 裝置代號 | 每次安裝產生一個 ULID，存在應用自己的空間，不放進文獻庫 |

## 3. `library.json`

```json
{
  "format": 1,
  "id": "01JCK3V7Q8Z9X5M2N4P6R8T0AB",
  "created": "2026-11-13T08:25:02.123Z",
  "notes_dir": "notes",
  "groups": [
    {
      "id": "01JCKA1B2C3D4E5F6G7H8J9K0M",
      "name": "物件偵測",
      "created": "2026-11-15T09:00:00.000Z",
      "modified": "2026-11-15T09:00:00.000Z",
      "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK"
    }
  ],
  "deleted_groups": [
    {
      "id": "01JCKA7P3Q5R7S9T1V3W5X7Y9Z",
      "deleted": "2026-11-15T11:20:41.002Z",
      "deleted_by": "01JCK3T1A2B3C4D5E6F7G8H9JK"
    }
  ]
}
```

| 欄位 | 意思 |
|---|---|
| `format` | 格式版本，整數。現在是 `1` |
| `id` | 文獻庫的代號，建立時產生，之後不變。兩台裝置的文獻庫代號相同，才能互相合併同步包 |
| `created` | 建立時間 |
| `notes_dir` | 筆記資料夾，相對於根目錄。現在一律是 `notes` |
| `groups` | 群組的定義，依建立的先後 |
| `groups[].id`、`name` | 群組的代號與名稱。名稱 1 到 100 個字，群組之間不分大小寫不可同名 |
| `groups[].created`、`modified`、`modified_by` | 建立時間；最後一次改名（或建立）的時間與裝置 |
| `deleted_groups` | 刪除記錄：被刪掉的群組代號、刪除的時間與裝置。合併兩台的文獻庫時，用來分辨「這台刪了它」與「那台從沒有過它」 |

較舊的 `library.json` 可能沒有 `groups`、`deleted_groups`，當成空的。`groups` 讀不懂時，文獻庫照樣打得開，只有群組的功能不能用。

## 4. 一篇文獻

### 4.1 什麼算一篇

`papers/` 底下直接一層的資料夾，裡面有一份讀得懂的 `paper.json`，就是一篇文獻。更深的層不看。

| 情況 | 應用怎麼處理 |
|---|---|
| 沒有 `paper.json` | 不是文獻 |
| `paper.json` 讀不懂（不是合法的 JSON、缺 `id`、某個欄位的型別不對） | 不列入目錄，不修、不刪 |
| `id` 以外的欄位缺少或是 `null` | 當成「不知道」：文字與時間是 `null`，清單是空的 |
| `format` 比應用認得的新 | 列入目錄，只能讀，不寫回 |
| 兩個資料夾的 `id` 相同（例如複製了資料夾） | 依資料夾名稱排序，只列第一個 |
| 材料清單列的檔案不存在 | 文獻照常列入，那項材料標成找不到 |

### 4.2 資料夾的名稱

資料夾名稱只給人看，應用不從它讀任何資訊；認文獻靠 `paper.json` 的 `id`。所以資料夾可以改名，也可以在 `papers/` 底下搬動。

加入時的名稱是 `<第一作者> <年份> - <篇名>`，缺哪一項就略過哪一項，三項都沒有時用原本的檔名。去掉 `\ / : * ? " < > |` 與控制字元，截到 60 個字、180 個位元組以內；已有同名的資料夾（不分大小寫）時加 ` (2)`、` (3)`。之後篇名改了，資料夾名稱不跟著改。

### 4.3 `paper.json`（描述檔）

```json
{
  "format": 1,
  "id": "01JCK3W2E4H6J8K0M2N4P6Q8RS",
  "short_name": null,
  "aliases": [],
  "added": "2026-11-13T08:30:11.045Z",
  "bib": {
    "title": "An Example Paper",
    "authors": [
      { "family": "Chen", "given": "Mei", "literal": null },
      { "family": null, "given": null, "literal": "Example Consortium" }
    ],
    "year": 2025,
    "venue": "Example Conference 2025",
    "doi": "10.1234/example.5678",
    "url": "https://arxiv.org/abs/2599.00001",
    "modified": "2026-11-13T08:30:11.045Z",
    "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK"
  },
  "materials": [
    {
      "id": "01JCK3W2E7T9V1X3Z5B7D9F1GH",
      "role": "source",
      "form": "pdf",
      "path": "source.pdf",
      "sha256": "01018b33…",
      "bytes": 5326548,
      "pages": 14,
      "pages_modified": "2026-11-13T08:30:11.045Z",
      "pages_modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
      "title": null,
      "provenance": {
        "method": "added-by-user",
        "time": "2026-11-13T08:30:11.045Z",
        "origin_name": "2599.00001v1.pdf",
        "proofread": null,
        "page_map": null,
        "source_sha256": null
      }
    }
  ],
  "groups": ["01JCKA1B2C3D4E5F6G7H8J9K0M"],
  "groups_modified": "2026-11-15T09:10:00.000Z",
  "groups_modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK"
}
```

（範例裡的 `…` 是為了排版縮短，實際的指紋是完整的 64 個字元。）

文獻本身：

| 欄位 | 意思 |
|---|---|
| `format` | 這份描述檔的格式版本 |
| `id` | 這篇文獻不變的代號 |
| `short_name` | 給人看、可以改的簡稱；可以沒有 |
| `aliases` | 這篇在別處用過的名稱（例如舊的編號），只供查找 |
| `added` | 加入文獻庫的時間 |
| `bib` | 書目，見下表 |
| `materials` | 材料清單：這篇的每一份檔，見下表與第 5 節 |
| `groups` | 屬於哪些群組（群組的代號），可以是空陣列 |
| `groups_modified`、`groups_modified_by` | 群組所屬最後一次改變的時間與裝置；從沒改過是 `null` |

書目 `bib`：

| 欄位 | 意思 |
|---|---|
| `title`、`venue` | 篇名、出處 |
| `authors` | 每位作者一個物件。姓與名分得開時填 `family`（姓）與 `given`（名）；分不開或是團體作者時只填 `literal`（整串名稱）。沒有作者時是空陣列 |
| `year` | 年份，整數 |
| `doi` | 一律存成小寫，不含 `https://doi.org/` 這類前綴 |
| `url` | 網址 |
| `cleared` | 使用者自己清空過的欄位名稱（`year`、`doi`、`url` 之中）。沒有時不寫這個欄位。自動補書目與同步都不會把這些欄補回來 |
| `modified`、`modified_by` | 書目最後一次被使用者修改的時間與裝置。應用自動補上空欄（DOI、arXiv 網址、年份）時不改這兩欄 |

每一項都可以是 `null`。

材料清單的每一項：

| 欄位 | 意思 |
|---|---|
| `id` | 這項材料的代號。劃線、筆跡以它指明畫在哪一份上 |
| `role`、`form` | 角色與形式，見第 5 節 |
| `path` | 檔案位置，相對於這篇的資料夾 |
| `sha256`、`bytes` | 指紋與大小。會一直變的材料（譯文疊加檔、重點筆記）是 `null` |
| `pages` | 頁數；不是 PDF 或還不知道時是 `null` |
| `pages_modified`、`pages_modified_by` | 頁數最後一次寫入的時間與裝置 |
| `title` | 這項材料自己的標題；可以沒有 |
| `provenance` | 來歷，見下表 |

來歷 `provenance`：

| 欄位 | 意思 |
|---|---|
| `method` | 怎麼來的：`added-by-user`（使用者加入）、`generated`（在應用裡產生） |
| `time` | 什麼時候成為這篇的材料 |
| `origin_name` | 加入時原本的檔名，只作紀錄 |
| `proofread` | 是否已校對：`true`、`false`，或 `null`（不適用） |
| `page_map` | 頁碼怎麼對應原文：`same-as-source`、`marked-in-text`（頁碼寫在文字裡）、`none`，或 `null` |
| `source_sha256` | 產生這項材料時原文的指紋。原文日後被換掉時，靠它知道頁碼可能失準 |
| `generated_from` | 只有產生的譯本 PDF 有：由哪一份譯文疊加檔產生（那一項的材料代號） |

規則：

- 一篇最多一項 `source`；可以沒有。
- 應用認材料只看 `materials`，不看資料夾裡有什麼檔名。資料夾裡清單沒列的檔，應用不動，應用的「檢查結果」會列出。

## 5. 材料

| `role` | `form` | 是什麼 | 預設檔名 | `sha256`、`bytes` |
|---|---|---|---|---|
| `source` | `pdf` | 原文 | `source.pdf` | 有 |
| `translation` | `pdf` | 使用者自己加入的譯本 PDF（`method` 是 `added-by-user`） | `translation.pdf` | 有 |
| `translation` | `pdf` | 產生的譯本 PDF（`method` 是 `generated`） | `translation-generated.pdf` | 有 |
| `translation` | `overlay` | 譯文疊加檔：版面紀錄加逐段的譯文 | `translation-overlay.json` | `null` |
| `digest` | `markdown` | 重點筆記 | `digest.md` | `null` |

預設檔名被占用時（資料夾裡的檔或清單裡的其他材料，不分大小寫）依序改用 `-2`、`-3` …，例如 `translation-generated-2.pdf`。`text` 這個角色保留給日後。

### 5.1 譯文疊加檔

一份 JSON 同時是「版面紀錄」（每一頁有哪些段落、在哪裡、什麼順序、原文是什麼）與逐段的譯文。原頁疊譯文、譯文檢視、產生譯本 PDF 都從它來。整篇重翻時另做一份新的，不覆寫舊的。

```json
{
  "format": 1,
  "source_material": "01JCK3W2E7T9V1X3Z5B7D9F1GH",
  "provider": "anthropic",
  "model": "claude-sonnet-5-5",
  "source_lang": "en",
  "target_lang": "zh-TW",
  "created": "2026-11-16T08:00:00.000Z",
  "created_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
  "modified": "2026-11-16T08:12:44.310Z",
  "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
  "segments": [
    {
      "id": "g0001",
      "page": 0,
      "bbox": [72.0, 600.0, 300.0, 700.0],
      "kind": "body",
      "size": 9.96,
      "source": "This is an example paragraph …",
      "target": "這是一段範例…",
      "status": "done",
      "error": null,
      "issues": ["missing_citation"],
      "modified": "2026-11-16T08:12:44.310Z",
      "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
      "service": { "id": "anthropic", "provider": "anthropic", "model": "claude-sonnet-5-5" }
    }
  ],
  "terms": [
    { "source": "token", "target": "詞元", "state": "learned", "batches": 2 }
  ]
}
```

檔頭：

| 欄位 | 意思 |
|---|---|
| `format` | 格式版本 |
| `source_material` | 翻的是哪一份原文（材料代號） |
| `provider`、`model` | 建立時選的引擎與模型。引擎的值有 `anthropic`、`openai`、`gemini`、`openai_compatible`、`deepl`、`google_translate`、`bergamot`（Firefox 翻譯），日後可能增加；機器翻譯的 `model` 是空字串 |
| `source_lang`、`target_lang` | 原文與目標語言（`en`、`zh-TW` 這類代碼）；原文自動判斷時 `source_lang` 是 `null` |
| `created`、`created_by`；`modified`、`modified_by` | 建立的時間與裝置；最後一次寫入的時間與裝置 |
| `segments` | 每一段。**陣列的順序就是閱讀順序** |
| `terms` | 這份譯本的術語；沒有時不寫出 |

每一段：

| 欄位 | 意思 |
|---|---|
| `id` | 依閱讀順序編的 `g0001`、`g0002` …，建立後不變 |
| `page`、`bbox` | 原文的頁序，與這一段在那一頁的範圍 `[x0, y0, x1, y1]` |
| `kind` | 段落的種類，例如 `body`、`caption`、`heading` |
| `size` | 主要的字級（點） |
| `source`、`target` | 原文與譯文。只有 `done` 的段落有譯文 |
| `status` | `pending`（待翻）、`done`（已翻）、`failed`（翻不出來） |
| `error` | `failed` 時原因的種類，其餘是 `null` |
| `issues` | 已翻的段落經自動檢查留下的問題代號：`missing_number`、`missing_citation`、`missing_formula`、`missing_url`、`untranslated`、`garbled`、`too_short`。沒有問題時不寫出 |
| `modified`、`modified_by` | 這一段最後一次更新的時間與裝置；建立時是 `null` |
| `service` | 實際翻這一段的服務：`id`（那台裝置的服務設定代號）、`provider`、`model`。沒有時不寫出 |
| `by_user` | `true` 表示這一段的譯文是使用者決定的（自己改的，或從並排比較挑的），之後的整批翻譯不蓋掉它。`false` 時不寫出 |

術語的每一項：`source`（原文詞）、`target`（譯法）、`state`、`batches`（出現過這個譯法的批數）。`state` 是 `candidate`（只出現過一批，不用）、`learned`（兩批以上同一個譯法，照用）、`user`（使用者改的）、`removed`（使用者刪的，不用也不再學）。

### 5.2 產生的譯本 PDF

由譯文疊加檔產生、版面與原文相同的 PDF，和使用者自己加入的譯本 PDF 是同一種材料，可以劃線、用筆刷。`provenance.generated_from` 指向它的譯文疊加檔。同一份譯文疊加檔再產生一次時，原地更新這一項（材料代號與檔名不變，檔案與指紋換新）。

### 5.3 重點筆記 `digest.md`

一份 Markdown，開頭是屬性區，每一點一行。

```markdown
---
paperreader_digest: 1
paperreader_digest_of: 01JCK3W2E4H6J8K0M2N4P6Q8RS
paperreader_source_material: 01JCK3W2E7T9V1X3Z5B7D9F1GH
paperreader_source_sha256: 01018b33…
paperreader_service: "Claude（Anthropic）"
paperreader_provider: anthropic
paperreader_model: "claude-sonnet-5-5"
paperreader_lang: zh-TW
paperreader_sections: [{"id":"question","label":"研究問題"},{"id":"method","label":"方法"}]
paperreader_created: 2026-11-16T08:00:00.000Z
paperreader_created_by: 01JCK3T1A2B3C4D5E6F7G8H9JK
paperreader_modified: 2026-11-16T08:00:00.000Z
paperreader_modified_by: 01JCK3T1A2B3C4D5E6F7G8H9JK
paperreader_proofread: false
---

# An Example Paper

## 研究問題

- 這是一個範例的點。 [p. 1](paperreader://open?paper=…&material=…&page=1) <!-- paperreader:point {"v":1,"id":"d-01jck5a7m3q9x2v8b4n6r0t1yz","section":"question","pages":[0],"segments":["g0003"],"created":"2026-11-16T08:00:00.000Z"} -->
```

| 屬性 | 意思 |
|---|---|
| `paperreader_digest` | 格式版本（1）。沒有這個鍵的檔不是重點筆記 |
| `paperreader_digest_of` | 文獻代號 |
| `paperreader_source_material`、`paperreader_source_sha256` | 依據的原文與當時的指紋 |
| `paperreader_service`、`paperreader_provider`、`paperreader_model` | 服務的名稱、引擎、模型 |
| `paperreader_lang` | 寫的語言 |
| `paperreader_sections` | 區段，依顯示的順序：一行 JSON 陣列，每項 `{"id", "label"}`。沒有這個鍵時照五個內建區段讀：`question`、`method`、`results`、`limitations`、`quotes` |
| `paperreader_created`、`_created_by`；`paperreader_modified`、`_modified_by` | 建立與最後一次寫入的時間與裝置 |
| `paperreader_proofread` | `true` 或 `false`，和材料清單那一項的 `provenance.proofread` 一致 |

內文：`# ` 是篇名，`## ` 是區段的名稱，兩者只給人看。每一點是**一行**清單項目：文字、每個頁碼一個回原文的連結（`page=` 從 1 起算）、行尾的 `<!-- paperreader:point {JSON} -->`。點的資料：`v`（1）、`id`（`d-` 加小寫的 ULID）、`section`（區段代號）、`pages`（原文的頁序，從 0 起算）、`segments`（產生時依據的段落代號，選填）、`created`。點的文字可以在筆記工具裡改；使用者自己加的段落原樣保留。

## 6. 筆記檔

位置是 `<文獻庫>/<notes_dir>/`，一篇一份。新建時檔名是那篇的資料夾名稱加 `.md`；之後篇名或資料夾改名，檔名不跟著改。**應用不靠檔名認筆記檔**，認的是屬性區的 `paperreader_paper`；它只讀 `notes_dir` 底下直接一層的 `.md` 檔。

```markdown
---
paperreader_paper: 01JCK3W2E4H6J8K0M2N4P6Q8RS
paperreader_modified: 2026-11-15T14:03:27.004Z
paperreader_modified_by: 01JCK3T1A2B3C4D5E6F7G8H9JK
tags: [paper]
---

# An Example Paper

## 整篇的想法

<!-- paperreader:thoughts -->
方法簡單，但實驗只在一個資料集上做。
<!-- paperreader:thoughts-end -->

## 劃線

<!-- paperreader:highlights -->
<!-- paperreader:highlight {"v":1,"id":"h-01jck5a7m3q9x2v8b4n6r0t1yz","kind":"highlight","material":"01JCK3W2E7T9V1X3Z5B7D9F1GH","file":{"sha256":"01018b33…","fingerprint":"9f2c4e…"},"page":{"index":6,"label":"7"},"rects":[[72.1,512.4,300.5,524.0]],"next_page_rects":[],"position":{"start":1834,"end":1902,"basis":"pdfjs-6.5.438"},"quote":{"exact":"This sentence was highlighted in the paper.","prefix":"In practice, ","suffix":" which limits"},"color":null,"created":"2026-11-15T13:40:00.000Z","modified":"2026-11-15T13:42:10.500Z"} -->
**p. 7**

> This sentence was highlighted in the paper.

^h-01jck5a7m3q9x2v8b4n6r0t1yz

這一句之後要回來查。

[在 PaperReader 開啟 p. 7](paperreader://open?paper=01JCK3W2E4H6J8K0M2N4P6Q8RS&material=01JCK3W2E7T9V1X3Z5B7D9F1GH&page=7&highlight=h-01jck5a7m3q9x2v8b4n6r0t1yz)
<!-- paperreader:highlight-end -->

<!-- paperreader:highlights-end -->

## 我自己加的

這段在標記之外，應用不讀、不改。
```

**屬性區**：檔案第一行是 `---`，到下一個 `---` 或 `...` 為止。應用認得三個鍵：`paperreader_paper`（屬於哪一篇）、`paperreader_modified`、`paperreader_modified_by`（應用最後一次寫這份檔的時間與裝置）。其餘的屬性原樣保留。

**標記行**：去掉前後空白後以 `<!-- paperreader:` 開頭、以 `-->` 結尾的行。

| 標記行 | 意思 |
|---|---|
| `<!-- paperreader:thoughts -->`、`<!-- paperreader:thoughts-end -->` | 整篇的想法的開始與結束 |
| `<!-- paperreader:highlights -->`、`<!-- paperreader:highlights-end -->` | 劃線區的開始與結束；新的劃線加在這裡 |
| `<!-- paperreader:highlight {資料} -->`、`<!-- paperreader:highlight-end -->` | 一條劃線的開始（帶資料）與結束 |

解析只看標記行，不看標題文字。一條劃線從它的資料行到它後面的**第一個**標記行；那一行是 `highlight-end` 才算完整，不完整的只能讀、不能改。不認得的 `<!-- paperreader:… -->` 當成區段的界線，原樣保留。

**劃線的資料**（資料行裡的 JSON，寫成一行；字串裡的 `<`、`>` 寫成 `<`、`>`）：

| 鍵 | 意思 |
|---|---|
| `v` | 資料行的格式版本，`1` |
| `id` | `h-` 加小寫的 ULID，也是 Obsidian 的區塊代號 |
| `kind` | 現在只有 `highlight`；`area`、`page-note` 保留給日後 |
| `material` | 劃在哪一項材料上 |
| `file` | `{sha256, fingerprint}`：劃線當時那份檔的指紋，與 PDF 閱讀元件讀出的文件識別碼；都可以是 `null` |
| `page` | `{index, label}`：頁序（從 0 起算）與頁面上印的頁碼（可以是 `null`） |
| `rects`、`next_page_rects` | 劃線範圍的矩形 `[左, 下, 右, 上]`；跨到下一頁的部分另列，沒有時是 `[]` |
| `position` | `{start, end, basis}`：該頁文字裡的起訖字數與算字數的依據；可以是 `null` |
| `quote` | `{exact, prefix, suffix}`：引句本身與前後各約 32 字；找劃線的位置主要靠它 |
| `color` | 顏色名稱；現在寫 `null` |
| `created`、`modified` | 建立時間、最後一次改短評的時間 |

**看得到的部分**：`**p. 頁碼**`、`> ` 開頭的引句、`^<劃線代號>` 那一行、短評、回原文的連結。**短評不在資料行裡**，是 `^<劃線代號>` 那一行之後、連結之前的文字；在筆記工具裡改了短評，應用讀到的就是改過的。連結的格式是 `paperreader://open?paper=<文獻代號>&material=<材料代號>&page=<從 1 起算的頁碼>&highlight=<劃線代號>`，點了開到那一篇的那一頁。

標題的文字（`## 整篇的想法`、`## 劃線`、「在 PaperReader 開啟」）由應用的介面語言決定，只給人看。標記以外的文字逐位元組保留。

## 7. 閱讀紀錄

`logs/reading-<裝置代號>-<年>-<月>.jsonl`。每台裝置只寫自己的檔，一行一筆、只往後附加、不改舊行。年月依事件的世界協調時間。

```json
{"id":"01JCK4…","t":"2026-11-13T09:02:44.310Z","device":"01JCK3T1…","paper":"01JCK3W2…","type":"position","data":{"material":"01JCK3W2E7…","page":7,"offset":0.35,"zoom":1.0,"left":0}}
```

| 欄位 | 意思 |
|---|---|
| `id` | 這筆事件的代號 |
| `t` | 發生時間。同一台裝置寫出的事件，時間一定比上一筆晚 |
| `device`、`paper` | 寫下它的裝置、關於哪一篇文獻 |
| `type`、`data` | 事件的種類與內容，見下表 |

| `type` | 什麼時候寫 | `data` |
|---|---|---|
| `open` | 打開一篇的閱讀畫面 | `{"material"}` |
| `position` | 讀到了某個位置 | `{"material", "page", "offset", "zoom", "left"}` |
| `status` | 手動標成已讀，或取消 | `{"read": true}` 或 `{"read": false}` |

| `data` 的欄位 | 意思 |
|---|---|
| `material` | 正在讀的材料代號 |
| `page` | 頁碼，**從 1 起算**，整數 |
| `offset` | 畫面頂端在這一頁的高度：0 是頁首，1 是頁尾 |
| `zoom` | 縮放倍率，或 `null` |
| `left` | 選填：畫面左緣在這一頁的位置，0 是頁面左緣、1 是右緣；沒有放大時是 0 |
| `read` | 是否標成已讀 |

**閱讀狀態**由事件算出，不存檔：最近一筆 `status` 是 `read: true` 就是已讀；否則有任何 `open` 或 `position` 就是讀到一半；都沒有就是未讀。所有裝置的事件依 `t` 排序，相同時依 `device`、再依 `id`。最後一行不完整就略過；不認得的 `type` 略過但保留在檔案裡。

## 8. 筆跡 `ink.json`

每篇的資料夾裡最多一份，第一次畫筆跡時建立。不列在材料清單裡。

```json
{
  "format": 1,
  "modified": "2026-11-16T08:30:11.045Z",
  "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
  "strokes": [
    {
      "id": "s-01jck5a7m3q9x2v8b4n6r0t1yz",
      "material": "01JCK3W2E7T9V1X3Z5B7D9F1GH",
      "page": 3,
      "color": "#d32f2f",
      "width": 2.5,
      "opacity": 1.0,
      "created": "2026-11-16T08:30:11.045Z",
      "points": [[72.5, 600.0], [80.25, 604.5]]
    }
  ]
}
```

| 欄位 | 意思 |
|---|---|
| `format` | 格式版本；缺少當成 1 |
| `modified`、`modified_by` | 這份檔最後一次寫入的時間與裝置 |
| `strokes` | 每一筆，依畫的先後 |
| `strokes[].id` | `s-` 加小寫的 ULID；筆跡建立後不改 |
| `strokes[].material`、`page` | 畫在哪一份材料的哪一頁（頁序） |
| `strokes[].color` | `#rrggbb`，小寫 |
| `strokes[].width` | 線寬（點），大於 0、最多 200 |
| `strokes[].opacity` | 不透明度，大於 0、最多 1；螢光筆小於 1。缺少當成 1 |
| `strokes[].created` | 畫的時間 |
| `strokes[].points` | `[x, y]` 的陣列，1 到 20000 個點 |

筆跡所在的材料被移除時，那幾筆留在檔裡。

## 9. 參考文獻清單 `references.json`

每篇的資料夾裡最多一份，由應用在閒著時讀原文抽出參考文獻後建立。不列在材料清單裡，跟著那一篇移到回收區、放回、備份、同步。

```json
{
  "format": 1,
  "modified": "2026-11-17T08:05:00.000Z",
  "modified_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
  "extraction": {
    "extractor": "links",
    "version": 1,
    "source_material": "01JCK3W2E7T9V1X3Z5B7D9F1GH",
    "source_sha256": "01018b33…",
    "created": "2026-11-17T08:00:00.000Z",
    "created_by": "01JCK3T1A2B3C4D5E6F7G8H9JK"
  },
  "entries": [
    {
      "number": 12,
      "label": "[12]",
      "text": "M. Chen and L. Wang. An example cited paper. In Example Conference, 2024.",
      "page": 9,
      "bbox": [72.0, 120.5, 300.2, 150.0],
      "doi": null,
      "arxiv": "2499.00002",
      "year": 2024
    }
  ],
  "judgments": []
}
```

| 欄位 | 意思 |
|---|---|
| `format`、`modified`、`modified_by` | 格式版本；最後一次寫入的時間與裝置 |
| `extraction` | 抽出的部分的檔頭：抽取的代號（`extractor`）與規則版本（`version`）、從哪一份原文（`source_material`）的哪一個版本（`source_sha256`）抽的、抽的時間與裝置。重抽時連同 `entries` 整份換掉 |
| `entries` | 參考文獻的每一條，依清單的順序 |
| `entries[].number`、`label` | 條目的編號（「[12]」的 12）與條目前的標記原樣；沒有編號的引用樣式是 `null` |
| `entries[].text` | 條目原文，不含標記，斷行的連字號已接回 |
| `entries[].page`、`bbox` | 條目起頭所在的頁序與那一段的方框 |
| `entries[].doi`、`arxiv`、`year` | 從條目讀出的 DOI（小寫、不含前綴）、arXiv 編號（不含版本號）、年份；讀不出是 `null` |
| `judgments` | 使用者對連結的判斷（文獻資訊裡的「是這篇」「不是這篇」「指定」），每項有自己的代號 `j-…` |

`judgments` 每一項的欄位：`id`、`kind`（`confirm`、`reject`、`manual`）、`paper`（判斷關於哪一篇文獻）、`entry_key` 與 `key_version`（重抽之後用來找回同一條的鍵）、`entry_text`、`entry_doi`、`entry_arxiv`（判斷時那一條的內容）、`created`、`created_by`。

## 10. 回收區 `.trash/`

**移除的一篇**：整個文獻資料夾搬到 `.trash/<移除的時間>-<資料夾名稱>/`，時間寫成 `20261113T083011Z`。裡面照樣有 `paper.json`。還原時搬回 `papers/`，去掉時間前綴，同名時加序號。代號不變，閱讀紀錄與筆記都接得上；筆記檔留在 `notes/`，不跟著搬。

**移除的一項材料**（原文以外的材料，例如一份譯本）：搬到 `.trash/<移除的時間>-<那篇的資料夾名稱> - <檔名>/`，裡面是那個檔，加上一份說明 `removed-material.json`：

```json
{
  "format": 1,
  "paper": "01JCK3W2E4H6J8K0M2N4P6Q8RS",
  "paper_folder": "Chen 2025 - An Example Paper",
  "removed": "2026-11-16T09:00:00.000Z",
  "removed_by": "01JCK3T1A2B3C4D5E6F7G8H9JK",
  "file": "translation-generated.pdf",
  "material": { "id": "01JCK…", "role": "translation", "form": "pdf", "path": "translation-generated.pdf", "…": "…" }
}
```

| 欄位 | 意思 |
|---|---|
| `paper`、`paper_folder` | 從哪一篇拿掉的（代號；移除時的資料夾名稱，只給人看） |
| `removed`、`removed_by` | 移除的時間與裝置 |
| `file` | 材料檔在這個資料夾裡的檔名 |
| `material` | 移除前材料清單裡的那一項，原樣 |

這種資料夾沒有 `paper.json`，所以不會被當成一篇文獻。

**永久刪除**會刪掉 `.trash/` 裡的那個資料夾，不能還原。那篇的筆記檔與閱讀紀錄不刪。使用者自己放進 `.trash/` 的東西，應用不動。

## 11. 變更紀錄檔

`logs/changes-<裝置代號>.jsonl`，每台裝置一份，外框和閱讀紀錄相同，一行一筆、只往後附加。它記下檔案裡看不出來的事，讓兩台裝置合併時分得出「這邊刪了」與「那邊新加的」：

| `type` | 什麼時候寫 | `data` |
|---|---|---|
| `paper-removed`、`paper-restored` | 一篇移到回收區、放回 | `{"folder"}`、`{}` |
| `paper-purged` | 一篇被永久刪除 | `{}` |
| `material-removed`、`material-restored` | 一項材料移除、放回 | `{"material"}` |
| `highlight-deleted`、`highlight-restored` | 刪掉一條劃線；合併衝突時選擇留下 | `{"highlight"}` |
| `strokes-deleted` | 刪掉筆跡或清除一頁 | `{"strokes": [代號…]}` |
| `thoughts-written` | 寫整篇的想法（有節流） | `{"sha256", "prev"}`：這一版想法的指紋，與它接在哪一筆之後 |
| `digest-point-deleted` | 重點筆記刪一點 | `{"material", "point"}` |
| `link-judgment-deleted` | 刪掉參考文獻連結的判斷 | `{"judgments": [代號…]}` |
| `sync-imported` | 匯入一份同步包之後 | `{"package", "from_device", "package_created"}`；`paper` 是 `null` |

新增與一般修改不記：那些項目自己帶著時間與裝置。

## 12. 備份檔與同步包

兩者都是不壓縮的 zip：文獻庫的檔放在 `library/` 底下（路徑和文獻庫裡相同），最後一項是清單 `manifest.json`。

| | 備份檔 | 同步包 |
|---|---|---|
| `manifest.json` 的 `kind` | `paperreader-backup` | `paperreader-sync` |
| 帶什麼 | 文獻庫裡所有一般的檔（含 `.trash/`；不含其他 `.` 開頭與 `.pr-` 開頭的項目） | 可以合併的檔：`library.json`、各篇的 `paper.json` 與材料、`ink.json`、`references.json`、有 `paperreader_paper` 的筆記檔、全部的紀錄檔。「只帶變更」時可能省略較舊的材料檔 |
| 清單的欄位 | `format`、`kind`、`created`、`library_id`、`files[]`（`path`、`bytes`、`sha256`） | 同左，加上 `package`（同步包代號）、`device`、`device_label`、`mode`（`full` 或 `changes`）、`since`、`base`（保留）；`files[]` 多一個 `included`，`false` 表示沒放進 zip |

兩種都不含翻譯服務的金鑰與應用的設定。

## 13. 版本與相容

| 規則 | 說明 |
|---|---|
| 每份 JSON 有 `format` | 現在都是 `1`。重點筆記用屬性區的 `paperreader_digest`；筆記檔的每條劃線與重點筆記的每一點用資料裡的 `v` |
| 遇到比自己新的版本 | 只讀，不寫回，同步時不合併 |
| 讀不懂的檔 | 不覆寫、不刪；應用的「檢查結果」列出 |
| 不認得的欄位 | 原樣保留。新版加的欄位經過舊版不會不見 |
| 加欄位不升版本 | 新增的欄位都是選填的：舊版當成不認得的欄位保留，新版讀舊檔時當成不知道 |
| 升版本時 | 會同時提供舊資料的處理方式：較舊的應用遇到新格式只讀不寫；轉換之前先備份；改名的欄位在一段時間內仍讀得懂舊名 |
| 固定的名稱 | 檔名、欄位名、種類與狀態的值都用英文，不隨介面語言改變 |

給別的工具的建議：只讀的工具照上面讀就好。要寫入的工具請照第 2 節「寫入」與「改之前先比對」，保留不認得的欄位，不改應用的代號與時間欄位，也不要動 `.pr-` 開頭的項目。

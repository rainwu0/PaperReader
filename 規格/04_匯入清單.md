# 匯入清單

狀態：定稿。照 `app/core/src/import.rs` 的程式寫成。**0.x 期間可能變。**

這份給外部準備整批匯入的人看：用腳本、書目軟體的匯出或手寫，把一批論文整理成應用收得下的樣子。應用不猜別的工具的資料夾或檔名慣例；照這份格式寫一份清單，應用照清單收。

## 1. 放在哪裡

一份名為 `paperreader-import.json` 的檔，放在要匯入的**資料夾**或 **zip** 的根目錄，名稱的大小寫要完全相同。清單裡每個檔的路徑都相對於這個根目錄。

壓成 zip 時，清單要在 zip 的根目錄，**不是包在一層資料夾裡**：在檔案管理員裡選取資料夾「裡面的」項目再壓縮，或在 PowerShell 7（`pwsh`）裡用 `Compress-Archive -Path <資料夾>\* -DestinationPath 匯入.zip`。直接把整個資料夾壓起來，zip 裡會多一層資料夾，應用找不到清單。

zip 裡的路徑要用 `/` 分隔（zip 格式本身的規定）。Windows 內建的 Windows PowerShell 5.1（`powershell.exe`）的 `Compress-Archive` 會寫成 `\`：zip 裡只要有一個項目的名稱含 `\`，應用整份不收，畫面說「zip 的路徑用了反斜線，請重新壓縮」。請改用 PowerShell 7 或其他壓縮工具重新壓縮。其他壓縮工具沒有逐一查證。

## 2. 例子

```json
{
  "format": 1,
  "kind": "paperreader-import",
  "papers": [
    {
      "csl": {
        "id": "zhao2024",
        "type": "paper-conference",
        "title": "DETRs Beat YOLOs on Real-time Object Detection",
        "author": [
          { "family": "Zhao", "given": "Yian" },
          { "literal": "RT-DETR Team" }
        ],
        "issued": { "date-parts": [[2024]] },
        "container-title": "CVPR 2024",
        "DOI": "https://doi.org/10.48550/arXiv.2304.08069",
        "URL": "https://arxiv.org/abs/2304.08069"
      },
      "short_name": "RT-DETR",
      "aliases": ["L001"],
      "files": [
        { "path": "L001/2304.08069v3.pdf", "role": "source", "form": "pdf" },
        { "path": "L001/zh-TW.pdf", "role": "translation", "form": "pdf",
          "title": "繁體中文譯本", "page_map": "same-as-source", "proofread": false }
      ]
    },
    {
      "files": [{ "path": "其他/某篇.pdf", "role": "source", "form": "pdf" }]
    }
  ]
}
```

第二篇沒有書目：篇名取原文的檔名（`某篇`），其餘空著，加入之後可以在應用裡改。

## 3. 格式

UTF-8 的 JSON，開頭可以有位元組順序記號，整份最多 16 MB。不認得的欄位一律忽略。選填的欄位寫 `null` 等同沒寫。

### 3.1 整份

| 欄位 | 型別 | 說明 |
|---|---|---|
| `format` | 整數 | 這一版是 `1`。比應用認得的新：整份不收，請使用者更新應用 |
| `kind` | 字串 | 固定 `paperreader-import` |
| `papers` | 陣列 | 每篇一項，1 到 10 000 項 |

整份不合（不是 JSON、找不到清單、`kind` 不對、`papers` 是空的等）時整份不收。下面每篇的問題只略過那一篇，其餘照收。

### 3.2 每篇

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `csl` | 物件 | 否 | 一筆 CSL-JSON 條目（Zotero、doi.org 給的那種），見 3.4 |
| `short_name` | 字串 | 否 | 短名。去頭尾空白；空的等同沒寫 |
| `aliases` | 字串陣列 | 否 | 這篇在別處用過的名稱（例如舊編號）。去頭尾空白，空的與重複的丟掉 |
| `files` | 陣列 | 是 | 這篇的每個檔，1 到 32 項，見 3.3 |

字串欄位（`path` 除外）最多 4096 個位元組。

### 3.3 每個檔

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| `path` | 字串 | 是 | 相對於根目錄，用 `/` 分隔，最多 1024 個位元組。不可以是絕對路徑；不可以含 `..`、`.`、空的段、反斜線、`:`、控制字元；任何一段不可以以 `.pr-` 開頭。**大小寫要和實際的檔名完全相同** |
| `role` | 字串 | 是 | `source`（原文）、`translation`（譯本）、`digest`（重點筆記）、`text`（抽出文字） |
| `form` | 字串 | 是 | `pdf` 或 `markdown`，和 `role` 的組合見下表 |
| `title` | 字串 | 否 | 這份材料自己的標題 |
| `page_map` | 字串 | 否 | 頁碼怎麼對應原文：`same-as-source`、`marked-in-text`、`none` |
| `proofread` | 布林 | 否 | 是否已校對 |
| `sha256` | 字串 | 否 | 檔案的 SHA-256（64 個十六進位字元，大小寫都收）。寫了，應用就比對，不符不收那篇 |

| `role` | 可以的 `form` | 一篇幾個 | 內容要符合 |
|---|---|---|---|
| `source` | `pdf` | 正好一個 | 不是空檔；前 1024 個位元組內有 `%PDF-` |
| `translation` | `pdf`、`markdown` | 不限 | PDF 同上；Markdown 是不是空檔、整份是合法的 UTF-8 |
| `digest` | `markdown` | 不限 | 重點筆記的格式（開頭的屬性區有 `paperreader_digest: 1`）；一般的 Markdown 筆記請用 `text` |
| `text` | `markdown` | 不限 | 不是空檔、整份是合法的 UTF-8 |

每篇一定要有原文：沒有原文的篇這一版不收（重跑同一份清單時靠原文的指紋認出已經收過）。同一個檔不可以列兩次（不分大小寫比對；前面的篇用過的檔，後面的篇不可以再列）。

### 3.4 書目（CSL-JSON）

只讀下表的欄位；其他欄位不收，應用在預覽裡提醒有哪些沒收（`id`、`type` 不算）。表裡的欄位型別不對，那個欄位當作沒有，不擋那一篇。

| CSL | 收成 | 規則 |
|---|---|---|
| `title` | 篇名 | 去頭尾空白。沒有篇名時取原文的檔名（去掉 `.pdf`） |
| `author` | 作者 | 每一項：有 `family` 就取 `family`（有 `given` 一起取）；否則取 `literal`；都沒有的那一項丟掉。不從 `literal` 拆姓名 |
| `issued.date-parts[0][0]` | 年份 | 整數或全是數字的字串，1000 到 9999。只有 `raw`、`literal` 時不猜 |
| `container-title` | 出處 | 去頭尾空白 |
| `DOI` | DOI | 存成小寫、去掉 `https://doi.org/`、`doi:` 等前綴 |
| `URL` | 網址 | 去頭尾空白 |

### 3.5 zip

- 收不壓縮與 Deflate（一般工具做的 zip）。加密的項目、符號連結：清單引用到就不收那篇，沒引用到就不看。
- 清單沒提到的項目（例如 `__MACOSX/`）一律不看；只有一個例外：任何項目的名稱含 `\`，整份不收（見第 1 節）。
- 最多 50 000 個項目；清單以外每個項目最多 4 GiB，加起來最多 64 GiB。

## 4. 預覽與結果的代碼

應用先掃描、列出預覽（會加入幾篇、略過幾篇與原因），使用者按「匯入」才寫。寫到一半取消或空間不足時，已加入的保留；**重跑同一份清單**時，已加入的篇因原文指紋相同而略過，可以接著做。

略過一篇的原因：

| 代碼 | 意思 |
|---|---|
| `bad-entry` | 某個欄位缺少、型別不對或值不認得（附欄位位置，例如 `files[1].page_map`） |
| `too-many-files` | 超過 32 個檔 |
| `bad-role` | `role` 與 `form` 的組合不對 |
| `no-source` | 沒有原文 |
| `multiple-sources` | 兩個以上的原文 |
| `bad-path` | 路徑不合規則、經過符號連結、不是一般檔案、zip 裡加密 |
| `duplicate-path` | 同一個檔被列了兩次 |
| `missing-file` | 檔案不存在、讀不到，或大小寫不同 |
| `form-mismatch` | 內容和 `form` 不符：不是 PDF、不是 UTF-8、空檔、不是重點筆記的格式、zip 項目壞了 |
| `checksum-mismatch` | 和清單寫的 `sha256` 不符，或檔案在掃描後被改過 |
| `already-present` | 原文已經在文獻庫裡（附那篇的代號） |
| `in-trash` | 原文在回收區裡（附那篇的代號） |
| `duplicate-source` | 前面一篇的原文和這篇相同 |
| `failed` | 寫入時的 I/O 錯誤 |

提醒（不擋）：`same-doi`（DOI 和文獻庫裡某篇相同，附那篇的代號）、`bib-fields-dropped`（書目有沒收的欄位，附鍵名，最多列 20 個）。

## 5. 加入之後的樣子

每篇建一個新的文獻資料夾（名稱用收成的書目組成），每個檔一項材料、順序照清單，檔名是 `<role>.<副檔名>`（同角色同副檔名的第二份起 `-2`、`-3`……，原文固定 `source.pdf`）。材料的 `provenance.method` 是 `imported`，`origin_name` 是清單 `path` 的最後一段；`proofread`、`page_map` 照清單；頁數在閱讀畫面打開時記下。重點筆記：不記指紋與大小，已校對取檔案屬性區的 `paperreader_proofread`（清單寫的不同時以檔案為準），`page_map` 一律 `marked-in-text`。

這一版的閱讀畫面打不開 Markdown 的譯本與抽出文字：它們列在文獻資訊的材料清單裡，可以用其他應用打開。

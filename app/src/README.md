# app/src：畫面

React 加 TypeScript（嚴格模式）寫的介面。顯示與操作；資料規則、檔案讀寫都不在這裡。

## 從哪裡看起

| 路徑 | 內容 |
|---|---|
| `main.tsx`、`App.tsx` | 進入點；把畫面疊起來（所有疊著的畫面都保留，只有最上面一層能操作）；打開應用時先到哪裡 |
| `api/` | **唯一呼叫指令的地方**，以及指令交回資料的型別（`types.ts`）。畫面不直接用 `invoke` |
| `strings/` | 介面文字，繁體中文一份（`zh-TW.ts`）；畫面用代碼取用 `t("home.add")`。出錯的訊息也在這裡，依錯誤種類取（`errorMessage`）；檢查找到的問題依種類取（`problemMessage`，不認得的種類有通用的一句） |
| `screens/` | 每個畫面一個資料夾：`home`（目錄、搜尋、篩選、排序、側邊欄）、`add`（加入的流程，含一次加多份；從另一台加入）、`reader`（閱讀、跳頁、大綱；另一台的閱讀位置）、`info`（文獻資訊）、`history`（閱讀紀錄）、`problems`（檢查結果）、`settings`（設定、同步頁與匯入同步包的預覽、回收區、關於） |
| `ui/` | 共用的元件（`components.tsx`）、圖示（含閱讀狀態的圓點）、樣式變數與共用樣式（`theme.css`） |
| `nav.ts` | 畫面之間的移動。用瀏覽器的歷史堆疊，Android 的返回鍵與返回手勢因此自然成立；面板（對話框、說明、側邊欄、搜尋列、排序選單、跳頁、大綱）也是堆疊的一層；畫面可以設「離開前的攔截」（文獻資訊有沒存的修改時先問一次） |
| `catalog.ts` | 首頁清單的整理：目前的檢視、搜尋、閱讀狀態篩選、排序。純函式，有測試（`scripts/catalog-test.mjs`）。檢視有全部文獻、未分組、群組三種（群組只算存在的，`inView` 帶存在的群組代號） |
| `library.ts` | 文獻庫與目錄在畫面這一側的狀態（向核心要結果，存起來給畫面用） |
| `checks.ts` | 打開文獻庫後在背景做的快速檢查（沒問題什麼都不顯示） |
| `prefs.ts` | 偏好（首頁排序、閱讀的選項）：存在應用的設定檔 |
| `pdfMeta.ts`、`pdfInfo.ts` | 加入之後讀出 PDF 自帶的篇名與作者：`pdfMeta.ts` 判斷好不好（純函式，有測試），`pdfInfo.ts` 讀並寫入 |
| `hooks.ts` | 回到前景時重新整理、深淺色 |
| `format.ts` | 只給畫面顯示用的整理（篇名、作者年份、「昨天」、閱讀紀錄的日期分組） |

## 規則

- 閱讀狀態、閱讀位置、什麼算已讀，一律由核心算好交回，畫面不推算。
- 「加入時間」用核心給的 `added`；舊的文獻沒有，排最後，彼此之間用代號的順序。
- 有搜尋或篩選、或看的不是全部文獻時，首頁不顯示「繼續閱讀」與「最近加入」。
- 首頁封面是原文第一頁的縮圖（`screens/home/thumbs.ts` 排隊一次畫一張，存在應用的快取，不進文獻庫）；沒畫好時是篇名首字的色塊。
- 首頁文獻列的「⋯」選單、側邊欄群組的選單都用導覽堆疊的 `groupMenu` 面板（`screens/home/useHomeActions.tsx` 管狀態與面板）。
- 出錯時顯示白話訊息：發生了什麼、資料有沒有受影響、可以怎麼做；不顯示代碼。
- 可以按的東西至少 48 像素見方；沒有文字的按鈕要有 `aria-label`。
- 畫面檔裡不寫中文（註解除外），文字都放 `strings/zh-TW.ts`。

## 檢查

```powershell
cd app
npm run typecheck   # tsc --noEmit
npm run lint        # Oxlint
npm run test:ui     # 介面邏輯測試（Node 內建測試器）
npm run build       # 打包到 dist/（Rust 的外殼編譯時要內嵌它）
```

# paperreader-core

文獻庫的核心函式庫：照規格讀寫手機上的文獻庫資料夾。不依賴 Android 與 Tauri，所有檔案操作都用標準函式庫，所以可以在電腦上直接測試，再編成 Android 版執行。

格式文件：[`docs/格式/文獻庫.md`](../../docs/格式/文獻庫.md)。

## 模組

| 模組 | 負責什麼 |
|---|---|
| `error.rs` | 所有操作共用的錯誤種類（沒有權限、空間不足、找不到、被別處改過、格式太新、唯讀、讀不懂、輸入不合法、其他 I/O） |
| `ids.rs` | 代號（ULID）、世界協調時間的字串、代號格式檢查 |
| `format.rs` | `library.json`、`paper.json`、閱讀事件的資料結構；欄位順序與可否為空照規格；不認得的欄位原樣保留；DOI 正規化 |
| `jsonio.rs` | 讀 JSON、不留半成品的寫入（先寫暫存檔再改名）、版本記號（檔案內容的 SHA-256） |
| `naming.rs` | 文獻資料夾的名稱：組成、去掉不合法字元、依「一個字」截斷、撞名加序號 |
| `reading.rs` | 三種閱讀事件（打開、位置、已讀）的種類、欄位範圍與驗證；判斷兩個位置算不算同一個 |
| `progress.rs` | 由有效的事件算出閱讀狀況：閱讀狀態、閱讀位置、各裝置的位置、最遠頁、最近一次閱讀的時間。純計算，不讀檔 |
| `store.rs` | 核心公開操作交換的共用型別（摘要、錯誤、同步預覽等）。核心與文獻庫之間唯一的通道是 `LocalLibrary` 的公開方法，不另設介面 |
| `local/` | 裝置本機的實作 `LocalLibrary`，直接讀寫一個資料夾，細分如下 |

`local/` 的各檔：

| 檔案 | 負責什麼 |
|---|---|
| `mod.rs` | 開啟文獻庫、清理暫存項目、記憶體裡的目錄、列出、取描述、取材料位置、動手前核對代號 |
| `scan.rs` | 掃描 `papers/` 一層與重新掃描 |
| `add.rs` | 加入一篇文獻（來源可以是檔案或資料流），以原文指紋判斷重複 |
| `edit.rs` | 修改書目，以版本記號偵測別處的修改 |
| `trash.rs` | 移除（移到 `.trash/`）、列出回收區、還原（代號相同的有兩個時取移除時間較晚的） |
| `events.rs` | 閱讀事件的紀錄檔：讀進來、附加上去（每台裝置、每個月一個 `.jsonl`）、記憶體裡的整理結果；紀錄檔有變就重讀；讀不了的紀錄檔略過（由「檢查」列成問題）。附加不對外 |
| `record.rs` | 三個寫事件的操作：記下打開、記下位置（與上一筆相同就不寫）、設定已讀；事件時間只往前走 |
| `status.rs` | 查詢閱讀狀況與「繼續閱讀」 |
| `check.rs` | 檢查文獻庫：只回報問題，不修、不刪 |

## 測試

測試在 `tests/`，每個檔案對應一個主題（例如 `add.rs`、`trash.rs`、`events.rs`）；`tests/common/mod.rs` 放共用的輔助函式。測試不依賴真正的 PDF，任意位元組就當作原文。執行：

```powershell
cargo test -p paperreader-core
```
